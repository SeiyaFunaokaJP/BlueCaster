# 斷音與連線問題
{: .no_toc }

聲音中斷、卡頓或停止？連線失敗，或位元率比預期低？本頁整理過去這類回報最後查出的原因，讓您在回報前先檢查常見原因；如果都不符合，也說明該提供哪些資訊。

## 請先檢查這些 {#checklist}

藍牙與 Wi-Fi、無線滑鼠和鍵盤、耳機接收器，以及房間裡所有其他藍牙裝置共用 2.4 GHz 頻段。USB 介面卡的天線很小，耳塞式耳機的天線更小，而且您的頭就擋在耳機與電腦之間。目前大多數「連線不佳」的回報，最後都是下列原因之一，每一項大約一分鐘就能檢查完。錯誤回報表單為每一項都提供了核取方塊，請勾選您試過的項目。

{: .note }
請一次只試一項，每試一項就聆聽幾分鐘。如果斷音消失，就找到原因了。

### 1. 關閉這台電腦上的其他藍牙介面卡

BlueCaster 透過 USB 介面卡串流時，旁邊的 Windows 藍牙（內建介面卡）仍會持續發射訊號。兩者共用同一個頻段，天線位置也往往很接近。電腦上的耳機 App 也會透過內建介面卡連線，讓耳機多出第二條連線（請參閱下一項）。BlueCaster 執行期間，請在裝置管理員中停用內建介面卡，至少在測試時停用。BlueCaster 偵測到其他使用中的介面卡時，會在首頁顯示提示。

一位長期測試者指出，連線不穩與編解碼器切換不順有兩個原因，第二個使用中的介面卡就是其中之一。

### 2. 只讓耳機保留一條連線

雙重連線（多點連線）讓耳機可以同時連線到手機與電腦。每條連線都會佔用無線電時間。開啟多點連線時，有些耳機還會提供較少的編解碼器、拒絕免持連線（因此看不到電量），或為另一個裝置保留一個編解碼器端點。耳機的專用 App 也算在內：即使您只用它查看電量或調整等化器，它也會在手機上或透過這台電腦的藍牙保持自己的連線。

測試方法：在耳機的 App 中關閉雙重連線，關閉手機的藍牙，並結束手機與電腦上的專用 App，然後從 BlueCaster 重新連線。

雙重連線就是那位測試者指出的另一個原因；中斷專用 App 的連線後，編解碼器切換順暢許多。曾有一副耳機因為仍連著開啟 LE Audio 的手機，拒絕了第一次連線。也有多款耳塞式耳機在手機或專用 App 介入時，提供給 BlueCaster 的編解碼器較少或位元率較低。Sony 耳機開啟多點連線時會關閉 LDAC。

### 3. 移動介面卡

- 使用 **USB 2.0 連接埠**，或一條短的 USB 延長線。USB 3 連接埠與線材會在 2.4 GHz 頻段產生雜訊，而且正好就在介面卡旁邊。
- 讓介面卡 **遠離其他無線接收器**，例如電競滑鼠與鍵盤的接收器、無線耳機的接收器和 Wi-Fi 天線。插在隔壁連接埠的接收器，正是這類問題的常見原因。
- 讓介面卡與耳機之間 **沒有遮蔽**。電腦放在桌子底下，中間隔著您和桌子，訊號會損失很多。用 USB 延長線把介面卡拉到桌面上，效果比其他方法都好。

有一台電腦沒有可供 AFH 參考的 Wi-Fi 介面卡，介面卡旁又有電競滑鼠的接收器，結果連結只能承載約 750 kbps，介面卡也把 79 個通道中多達 46 個標記為不良。距離介面卡一公尺的耳塞式耳機訊號仍然微弱，在接近位元率上限時，足以每隔幾分鐘就完全無聲一次。

### 4. 讓 2.4 GHz Wi-Fi 遠離藍牙連結

請讓這台電腦改用 5 或 6 GHz Wi-Fi；可以的話，手機與附近其他裝置也一起改用。如果必須保留 2.4 GHz，BlueCaster 會告知介面卡避開這台電腦 Wi-Fi 使用的通道（AFH，自動）。電腦沒有 Wi-Fi 介面卡、使用有線網路，或連線的頻段與路由器的 2.4 GHz 網路不同時，BlueCaster 就看不到這個通道。此時請查出路由器的通道（從路由器的管理頁面，或手機上的 Wi-Fi 分析 App）。如果路由器會自動切換通道，請在路由器上固定下來，再到 **介面卡 > 避開 Wi-Fi 通道 > 手動** 中輸入，例如 `6` 或 `11`。請參閱 [連線品質與 AFH](usage#link-quality)。

在壅塞的 2.4 GHz 網路上，LDAC 990 kbps 在 5 分鐘內遺失約 1,700 個封包。把路由器固定在一個通道，並將 AFH 設為「手動」避開該通道後，15 分鐘內只遺失 33 個。

### 5. 為連結保留餘裕

藍牙連結在最理想的情況下也只能承載略高於 1 Mbps。LDAC 990 kbps、LHDC V5 的 900 與 1000 kbps，以及高 bitpool 的 SBC XQ，幾乎沒有留下重新傳送的空間。真無線耳塞式耳機會把音訊從一耳轉送到另一耳，這也會佔用無線電時間，所以即使連結乾淨，900 kbps 以上對它們也很吃力。

- 試試 **ABR**（自適應位元率；LDAC、LHDC V5、aptX Adaptive，SBC 為自適應 bitpool），或降低一級：LDAC 660、LHDC V5 500、SBC XQ bitpool 29 到 36。
- 改用 **SBC 或 AAC**，看看斷音是否仍然存在。如果仍會斷音，原因就不是位元率。
- 檢查耳機本身：把耳機與手機配對，在手機上設定相同的編解碼器與位元率，在同一個位置聆聽。如果在手機上也會斷音，限制就在耳機這一側。

在一條只能承載 750 kbps 的連結上，500 kbps 以上的設定都會斷音，ABR 則完全沒有遺失。有一副平價耳塞式耳機的 SBC 能力允許 bitpool 53，但 SBC XQ 的 bitpool 超過 36 就沒有聲音。同一副耳機上，LHDC V5 會隨機斷音，LDAC 則很穩定。乾淨的連結確實承載得了：一台筆電的內建介面卡以 LDAC 990 kbps 串流 5 分鐘，遺失 0 個封包。

### 6. 更新 BlueCaster

有幾種聽起來像無線電問題的卡頓，其實是應用程式的錯誤。2.0.1 在虛擬音訊線延遲送出音訊時，會以快於即時的速度傳送，聽起來就是一秒有聲、一秒無聲。執行「中斷連線 > 連線」後，串流會一直卡頓，直到重新啟動應用程式。過時的藍牙堆疊在睡眠、長時間使用或多次重新啟動後會拒絕連線。這些問題在目前的版本中都已修正（[更新](usage#updates)）。如果更新後問題消失，就不需要回報。

## 解讀連線品質 {#link-quality}

**診斷 > 連線品質**（以及首頁的圖表）可以看出問題出在無線電、電腦還是應用程式。請在問題發生時截圖，並附在回報中。

| 您看到的 | 意義 | 指向 |
|:--|:--|:--|
| **訊號（與理想值之差）** 遠低於 0（約 -25 dB 以下） | 耳機的訊號抵達介面卡時，遠低於介面卡的理想範圍。這不是絕對值：0 代表理想，-30 代表比理想低 30 dB，因此 -30 仍可能播放，但已毫無餘裕 | 無線電：距離、您的頭與身體、介面卡的擺放位置 |
| **傳送佇列** 已滿、**傳送前捨棄的封包** 增加、位元率低於編解碼器的設定 | 封包等待無線電的時間太長；連結目前無法承載這個位元率 | 無線電或干擾，或位元率太高 |
| **跳頻 (AFH)** 數值跳動，或在遺失封包時停在 79 | 介面卡把出錯的通道標記為不良；停在 79 表示已無法區分好壞 | 干擾：Wi-Fi、其他接收器、第二個藍牙介面卡 |
| **擷取時捨棄的音訊** 增加，首頁顯示 **電腦忙碌** | 電腦沒有及時送出音訊 | 電腦：負載、擷取裝置、虛擬音訊線 |
| 所有數值都平穩且沒有資料，卻無聲或卡頓 | 連結沒有問題，電腦上也沒有捨棄任何資料 | 應用程式或耳機的解碼器：請附上診斷套件回報 |

電腦看不到接收端的情況。若要測量實際收到的內容，可使用 [對端接收器測試](usage#receiver)，以一台 Linux 電腦代替耳機。

## 由耳機決定的事 {#headphones}

有些「只有 400 kbps」或「沒有 LDAC」的回報，其實與連結無關。耳機會告知 BlueCaster 它接受哪些編解碼器與位元率，BlueCaster 和 Android 一樣照此處理。記錄中的 `remote supports ...` 這一行會顯示耳機提供了哪些項目。

- **Huawei FreeBuds** 必須先在 AI Life App 中設為「音質優先」並關閉多裝置連線，才會向電腦提供 LDAC，否則只列出 SBC 與 AAC。自 2.0.2 起，關閉自動選擇並選擇 LDAC 時，BlueCaster 會自動要求這個模式。
- **LHDC V5 耳機** 會公告最高位元率。有一副耳機在 App 的 96 kHz 模式下列出 400 kbps，在 192 kHz 模式下則列出 1000 kbps。OPPO Enco Free4 與 Enco X4 不論 App 如何設定，都只向電腦列出 400 kbps 與 48 kHz。在 2.0.2 中，LHDC V5 於 ABR 關閉的狀態下串流時，BlueCaster 會透過 OPPO 耳機自己的通訊協定要求 Hi-Res，並重新連線一次以套用（尚未在實際耳機上確認）。
- **ABR** 會把 LHDC V5 限制在 400 kbps 以下，與 Android 相同。
- 耳機 **為另一個裝置保留** 的編解碼器，在該裝置連線期間不會出現（[耳機連線到其他裝置時缺少編解碼器](usage#sep-in-use)）。

如何查看耳機提供的項目：[檢查耳機提供的編解碼器](usage#codec-fallback)。

## 連線失敗 {#connecting}

首頁上的錯誤訊息會說明發生了什麼事，[連線逾時](usage#connection-timeouts) 中的表格則解釋每一則訊息。與無線電有關的情況如下：

- **裝置沒有回應**（Page Timeout）：裝置未開機、超出範圍、第一次連線時未進入配對模式，或介面卡仍在使用 ROM 韌體。沒有載入韌體的 Realtek 介面卡掃描不到任何裝置、每次連線都逾時，或是能正常開啟卻始終無法串流；曾有一個韌體檔案其實是存下來的網頁。介面卡畫面會顯示韌體是否已載入。
- **連線已建立，但之後沒有傳輸任何資料**：原因可能是無線電環境，或耳機正忙於另一個裝置。請再試一次，或移動介面卡。
- **驗證失敗**，或記錄顯示 `signaling connection failed (0x66)`：耳機保留了先前配對的金鑰，通常是與這台電腦 Windows 藍牙的配對。`(0x67)`：耳機正被其他裝置佔用，例如開啟 LE Audio 的手機。請中斷其他裝置的連線，在耳機的 App 中關閉 LE Audio，讓耳機進入配對模式後連線一次；之後的連線會使用儲存的金鑰。
- 中斷連線後耳機 **無法連線到手機**：自 2.0.2 起，中斷連線會釋放連結。如果您是靠關機再開機，讓耳機在電腦與手機之間切換，請關閉 **自動重新連線**。

## 回報最後查出的原因 {#reports}

以下是目前所有與無線有關的回報，依最終查出的原因分類。

| 原因 | 回報 | 例子 |
|:--|:--|:--|
| **環境**：無線電、擺放位置、其他裝置 | 約三分之一 | 同一通道上的 2.4 GHz Wi-Fi、介面卡旁的電競滑鼠接收器、第二個使用中的藍牙介面卡、雙重連線與執行中的專用 App、真無線耳塞式耳機上沒有餘裕的位元率、小型耳塞式耳機的微弱訊號、其實是存下來的網頁的韌體檔案 |
| **耳機**：耳機向電腦提供哪些項目 | 約四分之一 | 只有在 Huawei 的音質模式下才提供 LDAC、LHDC V5 被耳機本身的模式限制在 400 kbps、透過 OPPO 的通訊協定設定 Hi-Res、為手機保留的編解碼器 |
| **應用程式**：BlueCaster 的錯誤，皆已修正 | 不到一半 | 使用虛擬音訊線時音訊以快於即時的速度傳送、「中斷連線 > 連線」後卡頓、睡眠或多次重新啟動後藍牙堆疊過時、中斷連線後仍保留連結、主動連線的耳機被誤判為金鑰錯誤、編解碼器快取隱藏了 LDAC、無法辨識的介面卡（某款晶片、某個 USB 類別、尚未生效的驅動程式繫結） |

值得注意的幾點：

- **卡頓與斷音的原因大約各佔一半**：一半是應用程式（2.0.1 與最初幾個 2.0.2 Beta 的時序錯誤），一半是環境。經過測量的兩個干擾案例情況相同：傳送位元率降到 550 至 800 kbps，傳送佇列塞滿，介面卡的通道對應變成 79 / 79。
- **連線問題大多出在應用程式**，而且幾乎都在同一個情境：耳機開機後自行發起連線。藍牙模擬器無法重現這個情境，因此這些修正都仰賴使用者提供的記錄。
- **「缺少編解碼器」與「位元率上不去」是耳機的決定**：耳機決定要向電腦提供什麼，通常受專用 App 的設定左右。
- 有些問題 **看起來像無線電問題，其實不是**：某個型號使用 AAC 時無聲（訊框格式）、耳機關機後 Windows 的輸出仍停留在虛擬音訊線上、切換編解碼器重新連線時喇叭會出聲幾秒、有線耳機也有聲音（系統回送的運作方式）。

## 回報 {#reporting}

如果上述檢查都找不到原因，請開啟一則 [錯誤回報](https://github.com/SeiyaFunaokaJP/BlueCaster/issues/new?template=bug_report.yml)，並勾選您試過的項目。以下資料有助於快速釐清無線問題：

1. 在 **診斷 > 回報問題** 中，將 **詳細記錄** 設為 **詳細（debug）**，然後重現問題。
2. **診斷套件**（開啟 **包含 HCI 擷取** 後按 **診斷套件 > 儲存…**，再按 **在 GitHub 上回報**）。套件包含串流健康狀態的記錄（傳送佇列、捨棄的封包、訊號、AFH 通道隨時間的變化），以及連線失敗時的 HCI 擷取，能看出封包在哪裡停住。
3. 問題發生時的 **連線品質截圖**。
4. 改用 **SBC 或 AAC**，以及使用 **較低位元率** 時是否也會發生。
5. 您在表單中對「雙重連線」、「另一個藍牙介面卡」與「Wi-Fi」問題的回答。
